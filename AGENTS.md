# AGENTS.md

Guide for AI coding agents (and humans) working on **Fallaway**, a solo card game for one standard 52-card deck. Start with `README.md` for what the game is and `RULES.md` for how it plays.

## Layout

| Path | What it is |
|---|---|
| `RULES.md` | The rulebook, written for a person playing a real deck. The source of truth for the rules. |
| `core/engine.ts` | The rules engine: the **only** implementation of the rules. Pure functions; every action returns a new state, or `null` if illegal. Also holds the advisor (`advise`, `adviseMove`). |
| `app/` | Web app (Vite + React 19 + TypeScript + framer-motion). `src/Practice.tsx` plays on screen; `src/guide.ts` + `src/GuideApp.tsx` + `src/GuideStage.tsx` guide a game with a real deck. See `app/README.md`. |
| `sim/sim.ts` | Bot simulator that plays `core/engine.ts`: skill ladder, per-decision skill, fairness, luck. |
| `DESIGN_NOTES.md` | Why each rule exists, with the simulation numbers, and the history of earlier versions. |
| `RUN_EXAMPLE.md` | A full narrated bot game, generated by the simulator. |
| `archive/` | Old simulators (v1–v4 rules), kept only so old results stay reproducible. Do not edit them for new work. |

## Commands

Run app commands from `app/` (`npm install` first). The scripts use `bun` and `node` (Node 22+; `.ts` files run directly).

- `npm run build`: type-checks `app`, `../core` and `../sim`, then writes the static site to `app/dist/`.
- `npm test`: both smoke tests (500 games each). The advisor wins about 54%, and the real-deck guide must equal the engine at every step.
- `npm run lint`: oxlint.
- `bun scripts/render.tsx`: server-renders the app (catches runtime errors without a browser).
- `npm run dev`: dev server on http://localhost:5199. The browser scripts in `app/scripts/*.mjs` need it running, plus Google Chrome installed at the macOS default path.
- From the repo root: `node sim/sim.ts report` (skill ladder) or `node sim/sim.ts run careful 41` (narrated game).

Before you finish a change: `npm run build && npm test && npm run lint` in `app/`.

## Rules of the codebase

- **One rules implementation.** Rule changes go in `core/engine.ts`, then `RULES.md`, then the real-deck guide (`app/src/guide.ts`), and `guide-smoke.ts` must still pass. Never reimplement a rule in the app or the simulator.
- **Rule changes need evidence.** Compare `node sim/sim.ts report` before and after, and record the numbers and the reasoning in `DESIGN_NOTES.md`. A rule stays only if removing it changes results; a decision stays only if replacing it with the obvious simple rule loses games.
- **One game, no difficulty levels.** Skill raises the win rate but never guarantees a win (like poker). Careful play wins about 54%, a beginner about 1 in 3.
- **No patch rules.** Fix pressure through the core loop (hunger, digging, fighting), not by adding corrective rules such as hidden clocks or escalation.
- **It must play on a real table.** Every rule has to be easy to run by hand with a physical deck. Write rules text with concrete examples, in plain English.
- **Saved games.** `localStorage` keys (`zoom-v4`, `zoom-guide-v4`, `zoom-mode`, `zoom-seen-intro-v4`, `zoom-stats-v1`) keep the game's old working name on purpose: renaming them would wipe players' saves and win records.
  The world menu added keys under the new name: `fallaway-world-v1` (the chosen world) and `fallaway-game-candy-v1` / `fallaway-game-moon-v1` (one saved on-screen game per world; Earth keeps `zoom-v4`). `fallaway-screen-v1` is in `sessionStorage` (the game screen open in this tab, so a reload stays in it).
- **Naming.** The game is *Fallaway*. "Zoom in" (dig) and "zoom out" (reveal the map) are names of actions, not of the game.

## Gotchas

- Simulator env flags (`SIMPLE=...`, `NOISE=...`, and the archived sims' rule knobs): in zsh, never pass them as one string variable (`env $FLAGS node ...`), because zsh does not split it and the run silently uses the wrong settings. Write them inline or use an array. Check that a run reproduces the numbers in `DESIGN_NOTES.md` before comparing variants.
- `app/vite.config.ts` uses `base: './'`, so the build works from any folder on any static host (it is deployed to GitHub Pages by `.github/workflows/pages.yml`; the canonical site is on Vercel).
- The site URL `https://fallaway.vercel.app/` is hard-coded in `app/index.html`, `app/public/robots.txt`, `app/public/sitemap.xml` and `app/public/llms.txt`. Update all of them if it changes.
